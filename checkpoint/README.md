# 2026-11-13 WIP 中间点

`download.json` 指定4个不超过8 MB的数据块，`artifacts.json` 列出212个存储文件及字节哈希。代码在 Git 中，固定工具运行时沿用 `repro/dependencies.json` 的既有发布。

| 模式 | 实际验证范围 |
| --- | --- |
| `check` | 212个文件的大小与存储哈希 |
| `audit` | 4个当前实现的76项绑定证据、原生报告 setup/hold/Fmax；不作公平优势或完整源证明声明 |
| `tests` | 67项当前证明、存储与反向检查；不等于全部历史测试均能在小包运行 |
| `projection` | 从原始阵列模型重建逐位映射和补齐位投影，结果必须与检查点逐字节一致 |
| `reproduce` | 真实四阶归纳必须产生已记录的写地址上界反例；表示失败被复现，不能称为等价证明通过 |

输出写入新的 `checkpoint_runs/` 子目录，原始证据不变。启动器阻止 Python 回读原开发工作区，不调用硬件烧录，不重新分配固定引脚。

部分证据以 `.json.gz`/`.il.gz` 保存，`ownpr_image_storage` 透明读取并计算原始哈希。手工执行历史 Yosys 命令前，须用 `copy_original` 恢复到新的运行目录，不要覆盖历史文件。

本包支持继续最新证明研究和审核四设计原生时序证据。它不包含每次历史实验的所有大缓存，也不承诺在缺少相应专用校准资料时运行全部历史测试或任意完整四设计冷流程。生产 SDPB 源证明准入仍关闭。

正式发布验证见 `checkpoint/validation.json`。“预期失败复现成功”与“功能证明成功”是不同状态。

当前源码的 `repro/Run-Small.ps1` 也在隔离目录实测通过完整20 MHz小 RTL流程，包括hold修复、STA与位流导出，耗时约340秒。原始 VexRiscv 评测 RTL及项目描述保存在 `examples/checkpoint_inputs/`，与保留的原厂展开来源哈希一致；这不意味着完整CPU源证明已经通过。
