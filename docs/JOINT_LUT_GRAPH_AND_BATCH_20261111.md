# 固定时钟边界下的组合改图、布局与路由共同搜索

本轮将评价器从“固定原语、只改等价源”扩展到普通 LUT 函数、连接、数量和独立位置可变的组合图。最终结果以 `results/vexriscv_joint_lut_graph_trial_001/engineering_summary.json` 和独立资格检查点为准。110 MHz 尚未达到；本轮也没有达到全局 WNS 改善 0.5 ns 的架构试点门槛。

最终 VexRiscv 独立验收 **88.6 MHz**，setup +0.001 ns、hold +0.133 ns，零违例；原厂报告 Fmax 88.610 MHz。110 MHz 原厂 STA 为 WNS −2.195 ns、TNS −350.689 ns、370 个 setup 违例。新增组合图与原厂全部 2,798 个 setup 和 2,798 个 hold 端点的最大 slack 偏差分别约 0.000622/0.000501 ns。局部频率合格不代表新算法的结构泛化守卫已通过；扩大采用仍有待办。

## 实现范围

`scripts/ownpr_lut_graph_feedback.py` 重建所有普通 LUT 输入及单元弧，刷新全部实测数据网络，并保留固定 ALU、宽 MUX、硬核和 I/O 的已校准内部弧。全部非 LUT 单元的网表与物理宏位置保持不变，FF 的源种子与终点 required time 来自已验证的单时钟、固定 I/O 时序边界。普通 LUT 的数量、类型、INIT、连接和独立位置可以变化；全局 setup/hold 均重新传播。

新增 LUT 不继承旧 LUT 的输入边；输出保持其逻辑位身份，实际新接收端从当前物理绑定取得。未移动接收端也使用改变后整树的延迟。候选仍须通过独立物理绑定、资源排他、有向 PIP 展开、配置检查、全状态边界 CEC 与最终原厂完整 I/O STA；模型本身不等于物理合法或签核。

组合映射使用可重算的函数 cut。五输入 cut 可改写为两个四输入余因子加一个 LUT 选择函数，各 LUT 的位置和对应路由共同决定候选结果。为使用原生较快的 I3，引脚按到达时间排列；不足四输入的函数以真值表无关 GND 引脚补为 LUT4，最晚信号放 I3。这个策略会改变实际路由与负载，不能仅凭单元弧更快就采纳。

`scripts/ownpr_joint_lut_search.py` 在常驻数据查询进程内完成映射、位置、增量路由、完整受影响树测时与全局 setup/hold 评分。另可从已实测候选中选出兼容的多个逻辑锥，重新组合并**整批重新路由和测量**；没有直接相加各个候选的收益或拼接未经检查的树。

## 发现并修正的目标函数错误

旧 `ownpr_alias_feedback.admissible()` 将负数 TNS 的改善方向写反，同时两个搜索的平分排序也偏向更负的 TNS。正确方向是向零增大，例如 −340 ns 优于 −350 ns。该错误会拒绝一些 WNS 不变但整体违例减少的候选，并可能选择更差的平分项。

已修正接受条件与排序，新增负例测试。此前通过完整 STA 的检查点依然有效，其资格不依赖启发式评分是否最优；旧搜索结果和源快照保留。不能将这个 bug 当成全部 110 MHz 差距的解释，也不能由修正代码推断大幅收益。

| 搜索 | 评价器中的 110 MHz WNS | 评价器中的 TNS | 说明 |
|---|---:|---:|---|
| 88.1 MHz 原检查点 | −2.251903 ns | −357.711043 ns | 已独立验收的参考 |
| `search_007` | −2.207466 ns | −357.538918 ns | 初次改图成交；仍含旧 TNS 选择规则 |
| `search_008` | −2.207466 ns | −344.037930 ns | 修正评分与覆盖后，22 次测量、3 次串行提交 |
| `search_009` | −2.194528 ns | −350.696950 ns | 从首轮兼容候选构造的五锥批量事务 |
| `search_010` | 同上 | 同上 | 修正 GND 读入表示；实际物理网络与静态链接完全相同 |

主目标优先采用 WNS 更好的批量候选；没有把 TNS 更好的另一候选当成相同实现。批量改写 5 个根、增加 2 个 LUT，不增加寄存器。状态、硬核、时钟、封装引脚、电气属性和接口周期不变。

## 真实器件集成中处理的问题

1. BRAM 时钟弧也出现在时序图中，使用固定时钟树的原已验证值；没有当作普通数据网络重建。
2. 普通 LUT 到配对 FF 的隐式数据线必须保持零线延迟；完整输出树的根部寄生值不能再次算入这条内部连接。宽宏根到 FF 则使用真实 OF→DI PIP，必须保留实际测量，不能一概设零。
3. 同物理 LUT 槽冲突、配对 FF 位置或数据关联改变、专用宏区域改写均被拦截；修改的独立 LUT 位置要经过器件布局校验。完整配置合法性仍由最终导入读回核验。
4. 原厂读入器拒绝新增 LUT 填充脚上的常量字面值，报告 PA2126 悬空输入。首轮导出失败发生在网表导入，尚未执行 STA。修复为设计中已有 GND 实例的网络；重新证明逻辑等价，并核对全部物理网络及静态链接完全相同，再从新目录导出。没有移动引脚或放松约束。

前六次启动失败均停留在新评价器的基线接入检查，未产生可验收物理候选。它们保留在 `search_001..006`。最初的 WNS 虽相同，TNS 差 0.02925 ns，逐弧对照定位到配对数据线重复计时；修正后 setup/hold 全部弧的源、目的、延迟和转换关系与参考一致。

## 验证及限制

17 项相关测试覆盖拓扑替换后旧边清除、未改兄弟接收端整树更新、固定边界拒绝、配对数据线、五输入重排的全部 32 种输入组合、最快引脚绑定、同槽冲突、TNS 方向以及既有树/时序检查。

`scripts/evaluate_joint_lut_graph.py` 在常驻搜索之外，用最终完整 wire 文件重新绑定并重建图；`scripts/compare_bidir_native_endpoints.py --rebuilt-model` 再与原厂完整报告逐端点比较。完整终态模型误差、独立频率、耗时和容量见摘要及对应 JSON，不能用搜索时的局部查询替代这些检查。

本轮未将新结构搜索应用到 UART/int2float/TMDS；保留它们原有合格实现只代表回退仍存在，不能报告新算法泛化通过。累计改善触及政策门槛时，实际结构守卫仍是扩大采用前的待办。下一阶段首先解除模型启动对旧 alias 检查点的依赖，为其他工程建立经过实测验证的边界模型，再运行原始新算法和 95% 守卫，分别报告原始结果与回退结果。

本轮只开放普通 LUT 改图，宽 MUX、ALU、FF 与 BRAM 的共同物理搜索仍未实现。多锥批处理之后全局 WNS 仍只有小幅改善，后续须处理跨这些固定宏的长互连，不能将普通 LUT 的成功准入包装成完整综合/布局/路由统一优化已经完成。

最终关键路径对照进一步解释了收益被抵消的位置：同一个 `slice$47604/D` 端点的 cell 部分从 4.244625 降至 3.993750 ns，减少 0.250875 ns；wire 却从 6.737625 增至 6.931125 ns，增加 0.193500 ns，净收益只剩约 0.057375 ns。这些分项不含源种子中的 clock-to-Q/时钟项。另一条 BRAM 地址竞争路径仍有 8.834625 ns wire，成为第二差路径。因此接下来的物理改进须覆盖这些跨宏连接，不能只优化 cut 内的逻辑级数。完整路径在 `critical_paths.json`。
