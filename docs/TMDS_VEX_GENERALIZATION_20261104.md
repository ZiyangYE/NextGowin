# TMDS / VexRiscv 通用优化推进（2026-11-04）

本轮优先推进 TMDS 与 VexRiscv。用户新增授权允许补齐缺失引脚；已新增两条评测分配，保留全部既有分配。VexRiscv 已完成带硬资源的自主布局与总线网络绑定，数据布线和最终 STA 尚未完成，不能把原厂校准结果作为自主实现频率。

## TMDS：53.5 → 92.5 MHz 完整 STA 闭合

当前实际布线报告 Fmax **92.506 MHz**；以 **92.5 MHz** 重新导出时，完整 I/O STA 为 setup **+0.001 ns**、hold **+0.204 ns**，setup/hold 均零违例。未增加寄存器或改变接口周期，固定引脚及原始零 I/O 延迟不变。相对上一轮 53.617 MHz 报告频率提升约 **72.5%**，仍未达到 150/200 MHz，也未证明优于原厂。

| 候选 | 报告 Fmax MHz | hold 状态 | 结论 |
| --- | ---: | --- | --- |
| 上一轮已闭合实现 | 53.617 | 通过 | 原基线 |
| 只跨比较器 ALU 边界重映射 | 54.773 | 失败 | 不采用 |
| 全部组合算术与 LUT 一起重映射，LUT4 | 76.998 | 失败 | 有效方向，未闭合候选 |

此前每个 ALU 都是综合 cut 的硬边界，整段算术/控制锥无法重构。本轮新增 `remap_ownpr_logic.py`，提供保留算术、仅放开比较器链、放开全部组合 ALU 三种策略。**BRAM、DSP、寄存器和 I/O 始终保留为命名边界**；“all”不把 BRAM/DSP 展开成普通 LUT。

新增初始 LUT5/6/7 宏打包及布局，使用已校准的独占 CFU 规则，与普通 LUT/FF 和进位链共同参与位置计算。随后完成增量布线、逐轮处理竞争 hold 输入、实际反馈的 LUT 引脚搜索与重新布局。186 个观察点的直接 CEC、配置位/连通性/完整原厂 STA 对比均通过；未用局部时序估计替代最后验收。

最新最坏到达路径约 **12.591 ns**，其中单元 **4.517 ns**、普通数据线 **8.074 ns**。之前原基线的相应最坏路径是单元 11.948 ns、线 8.476 ns。跨算术边界映射已经大幅减少单元延迟；**当前布线约占最坏到达路径的 64%**，下一重点是关键宽宏/FF 的共同布局、宏内空闲资源利用与拥塞感知增量重布线。不能据此声称已达到全局最优。

### DSP 编码缺项已定位，完整硬资源配置仍未验收

此前“DSP 有效载荷没有变化”的实验只做了逻辑/物理对象关联。继续核查 DLL 发现，编码器还会读取 tile 的逻辑实例列表；MULTALU27X18 未登记时，即使属性转换已写入 27 项物理属性，也会跳过配置。补用原厂 `addInstToGrid` 接口后，两处独立位置均产生配置差分，清除登记并解绑后完整有效载荷恢复。此前的失败证据保留，不能把早期零差分归因于 DSP 不需要配置。

两个位置的 BYPASS 差分均为 5 位，开启输出寄存器并同时将 CE 固定为 1 后均为 7 位；转换为相对 tile 坐标后逐位一致。新增的两位来自**组合模式改动**，尚不能分别宣称为寄存器位或 CE 位。逐镜像重算差分、核对绑定实例及完整恢复的证据见 [DSP 编码审计](../results/native_hard_site_inventory_001/dsp_encoding_membership_audit.json)。这仍是独立配置实验，不是已布线 DSP 的功能或 STA 验收。

此前同样的登记没有解决 BRAM 常规帧零差分；后续已定位到独立的专用逻辑指针，详见下节。历史零差分结果保留为缺少该步骤的对照。正式 packer 继续拒绝尚未整体验收的硬资源模式。

### BRAM 专用绑定与可复用接口

配置表 29/30 的处理函数读取物理 BRAM 的 `+0x678` 逻辑指针，而通用绑定只设置 `+8`。新原厂捕获中，10 个 BRAM 的这两个指针都指向同一逻辑实例；自主绑定缺少前者。补齐后，DPX9B 18 位、9 位和 SDPX9B 36 位在两处位置分别产生 10、12、10 位常规帧变化，相对位坐标逐位一致；对应物理属性也与原厂已布线实例一致，解绑完整恢复。此前的“只有尾部变化”问题因此已定位并修正。

对 18 位 DPX9B 单独将 `READ_MODE0` 从 0 改为 1，两处位置都只增加一个配置位。另在初始化位 0、72、18431 上做独立实验：分别影响尾部第 0、1、255 帧，每次只改变一个数据位及其后校验字段，普通配置帧不变；这覆盖了首位、跨帧和末位边界，尚不是全初始化空间证明。

新增 `scripts/native_hard_binding.py`，提供独占 BRAM/MULTALU27X18 的通用物理、专用物理及 tile 登记；检查类、子类型、坐标和占用，拒绝重叠绑定，并恢复原关联、属性与标志。真实 DSP/BRAM 编码试验已验证该接口及重叠拒绝。它是后端基础模块，尚未放开主 packer：硬资源路由、时钟、专用单元 STA 与完整 CPU 实现仍待接入。

逐镜像重算的[BRAM 配置审计](../results/native_hard_site_inventory_001/bram_configuration_audit.json)核对了 10 个原厂专用指针、三种模式的六组物理属性、读寄存器差分与六个初始化样本。新原厂捕获耗时 93.735 秒，仅作为校准，不能充当 VexRiscv 自主实现。没有移动已有引脚或改变实际工程的接口周期；模式/初始化变更只发生在隔离校准副本。

### 硬资源时序：8,080 条实际弧交叉核验

新增 `scripts/ownpr_hard_timing_model.py`。数据来自不执行原厂 P&R 的独立物理绑定：三个 BRAM 配置分别在两处位置查询全部数据端口；DSP 独立建立新版位级时序图。原厂完成 P&R/STA 的结果仅用于对照，逐项相等：DPX9B 840 条、SDPX9B 616 条、4 个 MULTALU27X18 合计 6,624 条，总计 **8,080 条**。

旧 DSP 标量查询表虽然能返回数值，却无法复现最终 STA。真正使用的是新版位级图：每个旁路 DSP 的 A/B→DOUT 有 1,656 条弧，诸如 A[26]→DOUT[0] 的不存在依赖不会成为零延迟弧。独立构建的完整图与四个原厂实例逐项一致；目前证据证明当前模式的位级模型，不证明外部负载依赖或所有 DSP 模式。

BRAM 已核对正沿时钟对应的时钟到输出、setup/hold、recovery/removal 原生矩阵。模型保留原生矩阵表示，拒绝未校准参数、负沿检查、不匹配端口类别及不完整查询，不把未返回数值当成零。一次新增拒绝检查遗漏了 SDPX9B 的 `RESET` 名称，回归发现后已修复；最终两项新测试通过，失败日志保留。

核验记录：[hard_timing_audit.json](../results/native_hard_site_inventory_001/hard_timing_audit.json)。这不等于硬资源完整 STA：原厂参照的脉宽表只显示有限行，其中可见 BRAM 要求 0.900 ns、最坏裕量 −0.222 ns，不能拿报告 Fmax 代替脉宽验收。寄存 DSP、更多模式、完整脉宽、实际时钟/多网路由及 CPU 整体闭合仍未完成。

以下实际接入已处理总线端口、BRAM 双时钟、受验证的禁用端口及未使用 ERR 输入 pad；完整硬资源布线、时钟配置与导出仍待闭合。

### VexRiscv：带硬资源的自主布局与网络绑定已运行

`run_ownpr_carry_place.py --hard` 现在把 BRAM/DSP 加入共同位置松弛，再用最小费用独占站点分配选择合法硬资源位置，并固定这些位置重新松弛周围逻辑。匹配代价是连接权重乘位置平方距离，属于初始布局方法，不宣称全局最优或最终 STA。

实际结果 `results/vexriscv_own_hard_place_007`：**28.203 秒**，10 个 BRAM、4 个 DSP、382 个 ALU、19 条进位链、3,685 个普通逻辑簇，全部 **284 个固定 I/O** 覆盖。硬资源占用 42 个独占 tile；逻辑/硬资源容量、占用及配对检查通过。经 8,582 个观察点 CEC 验证，保持原功能、状态和接口周期。

接入中补齐了三个问题：动态进位链头通过已有校准的 ALU 配置导入普通信号，增加 1 个 ALU；三种新常量输入组合完成配置差分及 18 个原厂实例对照；两个原本未使用的 ERR 输入补成 IBUF。新增 IBUF 只在证明其输出无消费者、输入原本未使用后才从组合 CEC 投影中移除，严格的状态/硬资源身份检查未放宽。

选中位置又在独立原厂 API 会话中同时绑定并恢复全部 14 个硬资源，未执行原厂 P&R。完整总线端口逐位核对，28 个原厂省略的常量输入单独记录；动态、未覆盖的缺失端口继续拒绝。随后形成 **6,024 个物理网络**，其中时钟网有 **1,546 个接收端**（1,526 个寄存器和 20 个 BRAM 时钟端口）。证据：`results/vexriscv_hard_nets_001`。

固定 J23 的时钟入口已从 DLL 图提取，并能到达全部接收端。原厂编码器对该自主时钟候选产生 4,093 位变化，恢复时零差异；但独立配置模型尚未覆盖 P20A 的命名空间歧义及 PCLKB0→P34A 等选择，因此仍不能批准完整导出。未进行引脚重分配。

首轮 300 秒数据路由超时，瓶颈为一个 391 接收端控制网的搜索；尚未证明资源耗尽。路由器新增按物理坐标缓存的精确曼哈顿估计，同坐标目标只保留最小到达代价，每个接收端搜索重新建立缓存。它不改变原估计公式、权重或接受标准；随机点集与原公式逐值一致，13 项相关测试通过。重测在 219.750 秒接通首个大网；旧版本在 300 秒内未接通该网，重测最终也在 300 秒路由预算结束时失败，共完整接通 1 个网络、累计连接 482 个接收端。共同完成的前 183 个接收端，其顺序/展开数/树节点数一致，耗时从 292.594 秒降至 123.312 秒；这不是完整路由等价或整体加速证明。
