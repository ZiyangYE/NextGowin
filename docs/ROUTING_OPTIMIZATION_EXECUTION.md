# 布线延迟定位与优化执行计划

日期：2026-11-02。状态：本轮计划已执行、证据已复核；通用 150 MHz 以上优势尚未达到。目标是定位延迟成因并完成受控物理实验。

1. 对已有原厂/自主报告逐条拆解数据网、单元、时钟插入；统计长线、位置跨度、扇出及路径类型。位置信息只代表端点，不当作实际布线路径长度。
2. 在 ctrl、int2float、router 上固定同一套引脚及 I/O 电气配置，维持原 100 MHz SDC，重跑原厂与自主网表。随后仅允许 IOB 寄存器打包，识别输出边界布线的影响。
3. 在同一固定引脚下，对两侧都设置 160 MHz 并允许 IOB，验证高频目标下的真实 setup/hold。新目标实验独立标记，不覆盖原始 100 MHz 或 FPGAFly 的原始约束。
4. 在内部逻辑主导的 sin 上，固定引脚，对照原厂、自主原配方、自主关闭新增复制、LUT4 紧凑配方。新映射必须通过实际网表 CEC，控制器件、时钟和后端设置。
5. 汇总哪些改动实际减少布线、哪些没有收益，以及是否将瓶颈迁移到内部路径。保存全部失败与退化；不把 I/O 优化所得提升冒充综合内核提升。

每次原生 P&R 设置截止时间，实验整体也设置一小时预算。SDK、原始 RTL、既有基线均只读，不烧录板卡。引脚取自既有原厂实现，双方使用同一份新 CST；它是受控实验条件，不声称为最优布局。

交付：路径归因程序、固定引脚/IOB/紧凑映射实验运行器、原始 JSON/日志、实际时序与资源对照，以及下一步优化决策。

## 执行结果

五项均已完成。根据第一批结果补做了三个同条件对照：核心寄存器保持不变仅提高目标至 160 MHz、仅允许输出寄存器进入 IOB、三个小设计仅将映射配方改成 LUT4。没有改动原始 RTL、SDC/CST 或 SDK。

共复核 43 个物理实验记录：37 个原生 P&R 完成，其中 15 个在各自目标下通过完整时序审计；6 个原厂 DLL 访问异常失败。失败、未闭合及退化全部保留。第一轮报告解析/转义名称检查故障修正后，对已完成原生输出重新审计，没有将解析故障算成网表失败。
