# Joint optimization checkpoint and baseline audit

## Completed physical result, under its original reporting policy

`results/vexriscv_wide_joint_trial_001/completion_audit.json` accepts native reported Fmax **90.380 MHz**, compared with the preceding own result 89.273 MHz (+1.2400%). Complete STA was at 110 MHz: setup WNS -1.973 ns, TNS -275.506 ns, 341 violations; hold +0.133 ns, zero violations. This is not 110 MHz closure. No Fmax-confirmation rerun was performed. Own routing, fixed-state combinational equivalence, connectivity/configuration and full I/O native STA/encoding completed. Hardware and full bitstream functional verification are not claimed.

Independent whole-model comparison covers 2,798 setup and 2,798 hold endpoint envelopes. Maximum arrival/required/slack error is below 0.000626 ns. The complete recorded attempt including closeout took 3,436.4 seconds, within its original 3,450-second deadline; the extra 120-second prebudget planning upper bound also stays below one hour. The checkpoint verifies 16 artifact hashes. The 28-test log in that packet predates subsequent policy/frontier changes and is preserved unchanged.

The transform adds 115 logic cells relative to its original physical source, keeping FFs, hard blocks and clocks fixed. The three other designs returned unchanged raw outputs under the same wide-mapping revision; exact-source historical native STA was audited. This proves safety on those inputs, not new performance improvement or the new four-design target.

## Evidence against restricting optimization to ordinary LUT cones

`results/global_joint_frontier_analysis_001` inventories all supplied setup/hold model endpoints by role and 16-by-16-tile region. VexRiscv setup violations split as follows:

|---|---:|---:|
| Register D | 188 | -157.298 |
| Register enable | 58 | -38.032 |
| Register reset/set | 11 | -11.352 |
| BRAM address | 38 | -35.188 |
| BRAM data | 26 | -22.954 |
| BRAM control/operand | 2 | -0.471 |
| Output I/O | 18 | -10.217 |

The latest worst reported path has 6.139 ns of data wire and 4.852 ns of data cell delay. A different near-worst reset-input witness has 13.023 ns of wire. The old November 5 figure of 75.1% wire is historical and must not be reused as this design's current universal fraction.

Current setup witnesses needing relief at 100 MHz span 33 launch groups; at 110 MHz they span 51. The top five account for 71/130 and 194/341 witnesses respectively. Artificially cutting every reported data-wire delay by 25% gives only a conditional 103.10 MHz ceiling on these witnesses. It is not a prediction of achievable routing, excludes alternate-path changes and hold, and assumes fixed cell/clock/I/O contributions.

`ownpr_global_timing_frontier.py` now ranks roots across all endpoint role/region fanins, with no fixed global worst-slack window, and is wired to wide-mapping search via `--global-frontier`. Source snapshots and per-round audits distinguish selected, offered, attempted and actually measured roots. The frontier is a bounded proposal scheduler, not proof of critical-path coverage or timing improvement. It currently does not enable state, clock or hard-resource movement.

Analysis-only runs on the four existing models show ordinary-LUT fanin reachability in 93/104 VexRiscv groups, 10/13 UART groups, 5/9 int2float groups and 8/11 TMDS groups. Forty selected roots represent all reachable groups in each analysis. UART and int2float's worst output groups are among those unreachable from ordinary LUT roots in the timing graph. Their launch/clock/I/O boundaries must be considered. The physical-input inventory also preserves unresolved absent checks and clocks for separate mode-aware audits rather than assuming them safe.

## Refreshed official scouting: no accepted denominator yet

`results/official_joint_baseline_scout_001` contains fresh official synthesis from checked RTL followed by explicitly labelled official P&R. An initially missing int2float RTL was regenerated byte-identically (SHA256 `9a936cacccd2c49d504073364e3b65ea39603e1f228ce01e27fa2dd4561e5b29`). TMDS's missing historical project descriptor was replaced by a new descriptor over the same RTL; the new elaborated result matches the original SHA256. The original failure is retained. These are fresh source reconstructions, not claims that deleted old intermediates are still present.

Common scouting uses 200 MHz, unchanged package/electrical constraints, complete min/max I/O constraints, native hold correction, place option 3 and route option 2. No IOB-register-disable flags are supplied; **native device defaults apply**. The original scout metadata's `input_output_iob_registers_allowed=true` describes omission of disable flags only and does not prove that IOB packing was enabled. SUG100-4.4.7E states that these IOB packing options default to false on GW5A(S)(T)-138.

The target-relative probe retains each official mapped netlist, preserves CST bytes and I/O budgets, and changes only the clock period using the uniformly predeclared rule `scouting_Fmax * 1.20 * 1.02`. Scouting frequencies are provisional references, not accepted baselines:

All four fail hold, and UART also has removal failures. Reducing the excessive 200 MHz scouting constraint did not solve the problem. These values cannot be used as accepted denominators, accepted frequencies or proof of a 20% gain. VexRiscv's reported Fmax also changed from 79.784 to 79.899 MHz, so its provisional target contract is not yet self-consistent. Full source/interface, physical/configuration and I/O coverage audits remain required before freezing any reference.

A documented native co-placement calibration on UART changes only `-co-place_io_registers 1`, retaining RTL/netlist, pins and SDC. Fmax falls to 136.020 MHz, hold remains -1.389 ns with 91 violations, and removal remains -1.128 ns. It is a rejected vendor calibration, not an own optimization or a valid baseline. SUG100 describes native hold correction as routing repair; enabling that option is not evidence that all I/O hold is repaired.

Native `.pr` files have been losslessly gzip-compressed, with original/decoded hashes and restoration instructions in `pr_lossless_storage*.json`. Their original raw paths are no longer directly readable; restore exact bytes before native import. Reports, netlists, constraints, failure conclusions and provenance remain available. No frozen handoff or current implementation dependency was removed.

## Research and independent consultation

Two completed consultations are `carbon-advice-20261112-four-design-joint-17.md` and `carbon-advice-20261112-open-architectures-18.md`. The second explicitly invited alternative architectures and challenges to the first. Candidate directions include arithmetic-preserving mapping and sequential/hard-boundary absorption; critical-versus-bulk fanout splitting; clock/IOLOGIC competition; and a single-pass per-sink timing-budget router. These are hypotheses with bounded experiments, not demonstrated 20% gains.

Independent checks of the advice: current TMDS indeed has zero ALU cells, while a historical official 100 MHz implementation used 37 ALUs and reported 136.437 MHz with setup/hold passing. This motivates arithmetic mapping ablation but does not establish a fair new baseline. A measured neighboring core-FF alternative does not prove a device-wide UART frequency ceiling. Moving an input capture clock later increases its hold requirement; it must not be assumed to remove input hold buffers. DSP register absorption needs sequential equivalence and mode/timing calibration beyond the existing fixed-state combinational proof.

[EqMap, ICCAD 2025](https://www.csl.cornell.edu/~zhiruz/pdfs/eqmap-iccad2025.pdf) uses e-graphs to escape structural mapping bias, reporting average LUT reduction without increased depth. That is not a Gowin Fmax guarantee; the current finite-cut mapper is not a full EqMap reproduction. [FPL 2025 interconnection-aware resynthesis](https://biblio.ugent.be/publication/01KMQW5B5CPZEDJMGYKMX4F8E6) motivates locality-aware restructuring/controlled duplication; accessible abstract evidence is preliminary. [The 2026 multi-die resynthesis preprint](https://arxiv.org/html/2602.19720v3) combines partition-aware resubstitution with packing/placement, but is submitted to TRETS rather than verified accepted publication. Its SLL reductions cannot be transferred into Gowin LONG WIRE or frequency improvement percentages.

## Next architectural work and acceptance

Resolve official hold closure and fixed-configuration final STA before freezing the four denominators; retain all failed baselines. Audit native physical state and legal clock/IO usage without changing external I/O timing budgets. In parallel algorithm development, compare arithmetic-preserving mapping and calibrated direct-FF/hard-register absorption against the current representation, then test per-sink timing budgeting and critical/bulk load splitting. Candidate selection and resource rules must remain shared across designs.

The latest frequency component is implemented as `target_relative_fmax_acceptance` with target multiplier 1.20 and STA headroom 1.02, used identically for official and own packets after their other gates are verified. Historical fixed-110-MHz packets keep their original policy. No new own packet has yet passed the latest target-relative protocol. Thirty-one targeted tests pass after the policy/frontier additions; no new global-frontier physical performance result is claimed. The goal remains active and unfinished.
