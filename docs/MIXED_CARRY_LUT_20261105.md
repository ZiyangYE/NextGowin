# 算术单元与普通 LUT 的受限混合打包

本轮将自研 VexRiscv 的最高合格频率从 65.2 提高到 **65.4 MHz**：完整 I/O STA 的 setup +0.007 ns、hold +0.134 ns，零违例，其他检查通过并生成位流。逻辑网表逐字节不变，LUT/FF/BRAM/DSP 数量均不增加。提升约 **0.307%**，不是整体巨大提升。

保留结果与重放入口：`results/vexriscv_carry_neighbors_001/summary.json`、`qualified_replay_checkpoint.json`。此前检查点与冻结 ZIP 保持不变。

## 器件能力与配置模型

原打包器把整个含算术链的 CFU 排他保留。原厂来源的引脚数据表明 ALU 使用槽位 0–5，其 SUM 对应 F0–F5；槽位 6、7 的普通 LUT 有独立输出。本轮只放开 **type-17 CFU、已校准 ALU mode 2、无配对 FF 的普通 LUT1–4 槽位 6/7**。未放开 FF、宽 MUX、其他槽位或其他 tile 类型的混用。

`native_carry_lut_sharing.py` 在两个位置分别比较 ALU-only、LUT-only、混合三种情况。第一次真正的混合编码对照中，ALU/LUT 真值均正确，但有 7 个控制配置位不符合旧的独立 ALU 模型。这不是资源不足，也不是可以忽略的误差。

混用时需要保留空独立 FF 控制组的正常默认字段，再叠加 ALU 模式；旧的全零 ALU 控制模板仅继续用于不共享的 CFU。修正后的 `native_carry_lut_sharing_005` 六组对照全部通过：

- 所有请求配置位与原厂编码一致。
- 混用前后引脚绑定一致，输出资源没有重叠。
- 完整普通配置位图符合独立成分组合，没有额外位图相互影响。
- 每次解绑后完整编码载荷恢复。

校准只调用原厂器件数据、绑定和编码接口，没有执行原厂 P&R。此前 001–003 的运行库、网表语法及引脚查询准备错误，以及 004 的真实控制位不匹配，均保留为失败记录。

`ownpr_carry_lut_sharing.py` 通过校准哈希和显式 placement 标记控制准入。算术容量检查、部分配置合并、原厂导入适配器使用相同混合属性模型；未共享时继续产生原有 ALU 属性，保持旧行为。

## 实际 CPU 试验与回退

`ownpr_pack_carry_neighbors.py` 根据真实 STA 临界连接，选择算术输入/输出附近的普通 LUT，并用所有相关连接的加权距离筛选位置。

首批 8 个 LUT 的完整布线与配置导出完成，但在 65.2 MHz 下 setup 为 −0.811 ns，共两个违例，报告 Fmax 61.926 MHz，因此拒绝。两个坏路径均经过被移动的 `ng_coopt_968`。它的一个输入连接从约 0.439 ns 缩短到 0.136 ns，输出扇出树的代价却抵消了收益，表明几何目标不能代替实际负载树延迟。

检查还确认 `net_4186` 和 `net_2815` 的 PIP 没有改变，不能把它们当作重布线退化。历史树修复没有找到可用目标。该过程发现并修复了恢复工具的空选择错误：空集曾进入一次空恢复并被标为 applied；独立比较证明所有 PIP 没变，也没有采用该结果。见 `empty_restore_audit.json`，相关空集合回归已通过。

`rollback_ownpr_carry_neighbors.py` 仅回退坏路径中涉及的已移动 LUT，最终保留 **7 个 LUT、5 个混合 CFU**。网表、FF/硬核位置、时钟树、固定 I/O 保持不变。

| 方案 | 实际约束 | setup WNS | hold WNS | setup 违例 |
|---|---:|---:|---:|---:|
| 原保留方案 | 65.2 MHz | +0.015 ns | +0.134 ns | 0 |
| 8 个混合打包 LUT | 65.2 MHz | −0.811 ns | +0.134 ns | 2 |
| 回退后保留 7 个 | 65.2 MHz | +0.054 ns | +0.134 ns | 0 |
| 最终频率资格验收 | **65.4 MHz** | **+0.007 ns** | **+0.134 ns** | **0** |

前两轮完整实现/导出分别为 323.312 与 323.343 秒，频率资格重放 202.172 秒。自第一次隔离校准起至最后相关检查完成，包含准备失败、校准、被拒候选、回退与导出的保守墙钟时间为 **3,391.580 秒**，未超过一小时。这仍不是从原始 RTL 开始的冷启动耗时。

24 项相关检查通过，包括旧 ALU/CLS 行为、混合模式准入、共享预算及仅按失败数据路径回退的测试。没有自动上板，不声称硬件运行已验证。

## 继续优化的方向

新后端为合法布局增加了选择，但直接相邻不代表整条路径更快。下一步应把新位置的输入线路、整个输出扇出树及相关路径预算共同用于候选评价，而不只依靠距离。部分算术链尾部与宽逻辑宏/FF 的更复杂共享仍须分别校准，不能由本轮结果推断支持。150/200 MHz 和通用优于原厂仍未完成。
