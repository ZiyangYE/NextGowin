# 全局路由反馈与关键单元合法化保护

当前最佳实现仍为 **66.7 MHz 完整 I/O 合格**，对应报告 Fmax 66.848 MHz。本轮三项完整物理实验均未超过它，未替换主检查点。90/150/200 MHz、通用显著优于原厂和 RTL 冷启动完整验收继续保持未完成。

## 实际接通的反馈

原全局路由入口对普通网络统一使用 `criticality=0.5`，内部引脚 STA 反馈主要用于后续修复。现在 `ownpr_route_design.bind` 可额外导出逻辑引脚到当前物理接收节点的对应关系，不改变标准网络连接文件。`ownpr_feedback_transport.py` 将经过来源哈希及所有报告终点校验的历史引脚关键性接入全局增量、分支重连和拥塞协商。

同名引脚只有在原语类型、参数、端口方向和对应输入位一致时才复用历史优先级。新建、重映射或缺少可靠反馈的接收端使用最高搜索优先级。共享物理接收点保守合并；未使用的引脚、时钟和常量不会改变数据网络的关键性归一化。标准 `nets.json`/`all_nets.json` 保持独立于搜索权重，权重和来源另存 `search_weights.json`。

本例核对 2,765 个 setup、2,765 个 hold 报告终点，向新绑定传递 14,926 个已知接收端的历史关键性，121 个无法可靠对应的接收端设为最高优先级。**这不是修改后电路的当前 slack，也不是完整的共享路径延迟预算保护。** 每项结果仍重新测量整棵路线树并做全部 I/O STA。

结构候选同时重映射 8 个多层逻辑 cut，净增加 **15 LUT、15 宽 MUX**，没有增加状态单元。CEC 核对原状态、硬核输入和端口观察点。布局会移动既有 FF，时钟树因此重新绑定和校准。

## 同条件物理对照

下面三项均使用同一重映射后的逻辑网表、固定封装引脚、电气条件及 90 MHz 的完整 I/O 约束。前两项的布局、时钟树、所有物理网络连接及公共路由算法源码哈希也完全一致，仅启用的搜索权重不同。

| 方法 | 报告 Fmax MHz | setup WNS ns | setup 违例 | hold WNS ns / 违例 |
|---|---:|---:|---:|---:|
| 统一权重对照 | 53.056 | −7.737 | 471 | +0.134 / 0 |
| 历史引脚关键性 | 63.452 | −4.649 | 328 | +0.134 / 0 |
| 历史关键性 + 近关键单元布局保护 | 66.740 | −3.872 | 365 | +0.134 / 0 |

历史关键性在这一次严格同布局对照中使报告 Fmax 提高 **19.594%**，但这是相对本次退化对照的改善，**不是相对 66.7 MHz 最佳实现或原厂的巨大优势**。三个报告值均不能冒充对应频率已验收；三项 90 MHz 都失败，其他原厂最终检查及位流导出通过。

完整时限：加权候选从重新获取反馈、映射、证明至导出共 **603.000 秒**；布局保护候选共 **606.031 秒**。无权重对照复用了完全相同的网表、布局和时钟证据，仅完整重跑数据 P&R/检查/导出，耗时 **556.812 秒**。该对照不是相同工作量的 RTL 冷启动；作业曾并行执行，不据此宣称通用速度倍率。所有实验均在其独立的一小时上限内。

来源和可重复审计：`results/vexriscv_feedback_comparison_001/routing_control.json`，由 `scripts/compare_feedback_routing.py` 逐项检查上述哈希和完整出口状态后生成。

## 为什么还没有超过最佳实现

第一项加权候选为了安置新宽宏，原合法化器将普通 LUT `ng_coopt_2535` 从 [67,100,1] 移到 [67,104,7]。它的历史最坏 setup 余量只有 **0.220128 ns**，但至 `ng_coopt_2899` 的慢角上升连线从 **0.365625 ns** 增加到 **1.431000 ns**，超过原余量。这是原厂整树查询结果，不是曼哈顿距离估计。

新增的布局保护在腾挪普通簇时锁住历史 setup ≤0.5 ns 或 hold ≤0.15 ns 的单元。本例有 45 个；被明确重映射的根及其配对 FF 可以作为此次变换的一部分移动，其他近关键单元不得被顺带挪动。保护后 `ng_coopt_2535` 的原位置保留，`net_8175` 四个转换/角的线延迟均恢复到基线值。新宽宏改用 [67,102]。两组候选的逻辑网表和引脚反馈捕获哈希完全相同。

两组分别移动 51 个仍存在的原普通 LUT 簇；包括重映射根的配对 FF 在内，既有 FF 实际位置变化分别为 15 / 13 个。保护并未简单消除所有挪位，而是改变了允许挪位的对象和目标位置。逐端点证据：`results/vexriscv_feedback_comparison_001/displacement_evidence.json`。

保护后的最差路径为 8 级逻辑，但仍含 **11.033 ns 数据布线 + 3.851 ns 单元/C2Q**。其中 ALU SUM→`ng_coopt_1079` 为约 **2.292 ns**，`ng_coopt_1079`→`ng_coopt_2535` 为约 **2.346 ns**。这两棵网络的源、全部接收端与实测延迟都与最佳基线相同，不能把它们说成本轮路由退化；它们是仍未消除的既有长连接。其他路径改善后，竞争瓶颈继续限制整体频率。

## 验证和剩余工作

最终相关回归 **35 项通过**，见 `results/feedback_coopt_regression_001.log`。覆盖历史关键性传递、未知/共享接收点、逻辑变更拒用旧优先级、近关键布局保护、增量路由、宏合法化和多层 cut 选择。新增真实器件检查确认接收端映射与原厂端点一致，且原始网络文件不变；原厂配对 LUT→FF D 的直接连接没有普通路线节点，单独按该约定核对。最初测试中的元组/JSON 列表比较及直接连接假设已修正，失败日志保留。

本轮没有编程硬件、运行原厂 P&R 或采用开源器件数据库。工作区仍以 40,000,000,000 字节为唯一容量上限。

下一重点是把剩余算术边界长连接、映射新增输入负载、完整负载树代价以及 setup/hold 余量共同纳入候选选择，避免仅改变逻辑层数或只锁住一小段历史关键窗口。当前新增能力仍是历史优先级和近关键挪位保护，不是完整的动态时序预算优化器。

